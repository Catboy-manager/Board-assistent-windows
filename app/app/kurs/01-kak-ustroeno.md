# Глава 1. Как устроено веб-приложение

> **Цель главы:** понять картину целиком — кто, зачем и как разговаривает, когда вы открываете сайт. После этой главы слова «сервер», «HTTP», «JSON», «порт» перестанут быть чёрным ящиком.

---

## 1.1 Самая простая аналогия

Представьте заказ в ресторане:

- **Вы (браузер)** — посетитель. Вы садитесь и говорите: «Пожалуйста, меню».
- **Кухня (сервер)** — тот, у кого есть всё: продукты, рецепты, холодильник.
- **Официант (протокол HTTP)** — способ донести заказ и вернуть блюдо.

В сайте нет «волшебства»: где-то лежат **файлы** (страница, картинки, код), и есть **программа**, которая их отдаёт и принимает от вас данные. Программа, которая раздаёт файлы и отвечает на запросы, и называется **сервером**.

```text
  ┌─────────────┐   GET / HTTP/1.1        ┌──────────────────────┐
  │   Браузер   │ ───────────────────────▶│     Ваш сервер       │
  │ (клиент)    │                         │  node server.js      │
  │             │ ◀───────────────────────│                      │
  └─────────────┘   200 OK + html/css/js  │  читает public/      │
                                          │  читает/пишет data/  │
                                          └──────────────────────┘
```

Важно: **сервер ничего не помнит сам по себе**. Он умеет отвечать на запросы. Память (что вы добавили карточку) — это отдельная история, про неё глава 7.

## 1.2 HTTP: язык запросов

HTTP (HyperText Transfer Protocol) — очень простой текстовый протокол. Запрос выглядит примерно так (это то, что реально уходит по проводу):

```http
GET /api/data HTTP/1.1
Host: localhost:8080
Accept: application/json
```

А ответ — так:

```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8
Cache-Control: no-store

{"board":{"columns":[{"id":"c1","title":"Задачи"}],"cards":[]}}
```

Разберём по частям:

| Часть | Что это | Примеры |
|---|---|---|
| **Метод** | Что мы хотим сделать | `GET` — получить, `POST` — создать, `PUT` — сохранить целиком, `DELETE` — удалить |
| **Путь** | Какой ресурс | `/api/data`, `/css/style.css`, `/` (корень = главная) |
| **Заголовки** | Служебные метаданные | `Content-Type` (что за данные), `Host` (к кому) |
| **Тело** | Полезная нагрузка (не всегда) | JSON вида `{"title":"Купить молоко"}` |
| **Статус** | Итог | `200` — ок, `404` — не найдено, `500` — сервер сломался |

### Статус-коды, которые встретятся в курсе

- **200** — «всё хорошо, вот данные».
- **400** — «вы прислали мусор» (например, карточка без названия).
- **401/403** — «нет доступа» (не тот ключ / запрещённая папка).
- **404** — «такого нет».
- **500** — «у меня внутри что-то упало» (ошибка кода).

> 📌 Практический навык: **всегда смотрите статус-код**. 90% «ничего не работает» — это 404 (опечатка в пути) или 500 (ошибка в сервере, текст которой напечатан в терминале).

### Проверка руками (уже сейчас!)

Откройте терминал и напишите:

```bash
curl -i http://localhost:8080/api/ping
```

Если проект запущен, увидите заголовки + `{"ok":true}`. Это и есть настоящий HTTP-обмен — браузер делает то же самое, только в графическом виде.

Можно и без терминала: откройте в браузере `http://localhost:8080/api/data` — увидите JSON доски.

## 1.3 Адрес: хост, порт, localhost, LAN

Компьютер в сети определяется **IP-адресом**, а программа внутри — **портом**.

```text
http://192.168.1.100:8080/api/data
         │              │    └── путь
         │              └─────── порт (номер «двери» программы)
         └────────────────────── адрес компьютера в домашней сети
```

- `localhost` = `127.0.0.1` = «этот же компьютер». Доступно только вам.
- `192.168.x.x` / `10.x.x.x` / `172.16–31.x.x` — типичные домашние адреса (LAN).
- **Один и тот же компьютер может держать много портов**: 8080 — HTTP, 8443 — HTTPS, 9222 — отладка браузера. Не путаются, потому что это разные «двери».

В этом проекте:

```text
http://localhost:8080   ← открывать на самом ПК (микрофон работает)
http://192.168.1.100:8080 ← открывать с телефона в той же Wi-Fi-сети
https://…:8443          ← то же самое, но зашифровано (глава 12)
```

**Задача 1.1.** Узнайте IP своего компьютера (`ip -o addr | grep -w inet` в Linux, `ipconfig` в Windows) и откройте `http://СВОЙ_IP:8080` с телефона. Убедитесь: доска открылась. Если нет — это тема для главы 12 (брандмауэр/одна сеть).

## 1.4 JSON — валюта общения

Браузер и сервер обмениваются почти всегда **JSON** (JavaScript Object Notation) — текстом, который легко превратить в структуру данных и обратно:

```json
{
  "board": {
    "columns": [{ "id": "c1", "title": "Задачи", "color": "#f5b7b1" }],
    "cards": [{ "id": "card_x1", "columnId": "c1", "title": "Купить молоко", "done": false }]
  },
  "events": []
}
```

Пары «ключ: значение», списки в квадратных скобках, вложенность — всё как объекты в JavaScript, только текстом.

Две функции, которые делают всю работу:

```js
JSON.stringify({ a: 1 })        // объект → строка '{"a":1}'
JSON.parse('{"a":1}')           // строка → объект { a: 1 }
```

> ⚠️ Ловушка новичка: JSON — это **строгий** формат. Ключи только в кавычках, в конце нельзя ставить запятую, одинарные кавычки не годятся. Ошибка парсинга = «Unexpected token» в консоли.

**Задача 1.2.** В терминале:

```bash
node -e "console.log(JSON.stringify({title:'Привет', tags:['курс','канбан']}))"
node -e "console.log(JSON.parse('{\"n\":5}').n * 2)"
```

Первая строка должна вывести валидный JSON, вторая — `10`.

## 1.5 Два больших мира: клиент и сервер

| | **Клиент (браузер)** | **Сервер (Node.js)** |
|---|---|---|
| Код | HTML + CSS + JavaScript в `public/` | JavaScript с `require(...)` |
| Запускается | Открытием страницы | `node server.js` |
| Может | Рисовать, слушать клики, хранить в `localStorage`, звать API | Читать/писать файлы, смотреть в сеть, запускать процессы |
| Не может | Читать файлы вашего ПК напрямую, обходить политики браузера | «Видеть» экран — у него нет DOM |
| Число экземпляров | Сколько угодно вкладок/телефонов | Один (или несколько одинаковых) |

Одна и та же языковая конструкция — **JavaScript** — но с разными возможностями: у браузера есть `document`, у сервера — `require('fs')`.

### Правило NeuroBoard

```text
Браузер:  «нарисовать и спросить»     fetch('/api/data') → отрисовать колонки
Сервер:   «знать и сохранить»          прочитать db.json → вернуть JSON
```

Браузер **не хранит истину**. Он может сделать `localStorage` для скорости, но источник истины — файл на диске у сервера. Поэтому с телефона и с ПК вы видите одну и ту же доску.

## 1.6 Живая анатомия: что происходит при открытии NeuroBoard

Когда вы вводите `http://localhost:8080`:

1. Браузер отправляет `GET /`.
2. Сервер смотрит на путь: это не `/api/...`, значит нужен файл → читает `public/index.html` и отдаёт его (`server.js:1176`).
3. В HTML подключены `style.css`, `app.js` — браузер шлёт ещё запросы на каждый (`GET /css/style.css`, `GET /js/app.js`, …).
4. `app.js` выполняется и вызывает `fetch('/api/data')` (`public/js/app.js:42`).
5. Сервер отвечает JSON из памяти/файла (`server.js:1105`).
6. JavaScript рисует колонки и карточки в DOM, навешивает обработчики кликов.
7. Вы кликаете/тянете — браузер меняет DOM, а при важных изменениях шлёт `PUT /api/data`, и сервер сохраняет `data/db.json`.

```text
 GET /            GET /app.js        GET /api/data        PUT /api/data
Браузер ────────▶ сервер ──────────▶ сервер ────────────▶ сервер
   ◀── index.html  ◀── код JS         ◀── {columns,cards}    сохраняет db.json
                                          рисуем доску        ◀── {ok:true, db:...}
```

Полный роутер проекта — `server.js:1097` (`handleRequest`). Там по одному `if` на каждую фичу:

```js
if (req.method === 'GET' && p === '/api/data') return json(res, 200, publicDb());
if (p.startsWith('/api/movies')) { if (await movies.handle(p, url, req, res)) return; }
if (p.startsWith('/api/notify')) { if (await notify.handle(p, url, req, res)) return; }
...
return json(res, 404, { error: 'not found' });
```

Эту схему вы повторите сами в главе 6.

## 1.8 Что такое Node.js в двух словах

**Node.js — это браузерный JavaScript, отвязанный от браузера** + набор модулей для системной работы (`fs`, `path`, `http`, `child_process`).

```js
const fs = require('fs');                 // читать/писать файлы
const http = require('http');             // строить сервер
const { spawn } = require('child_process'); // запускать другие программы
```

Плюс очень важная особенность: **Node однопоточный и асинхронный**. Долгая операция (прочитать файл, полезть в интернет) не блокирует сервер — он принимает другие запросы, а по готовности получает колбэк. Поэтому один процесс спокойно обслуживает и вас, и телефон, и Telegram.

```js
// ❌ НЕ так (блокирует весь сервер на время чтения):
const text = fs.readFileSync('/big/file');

// ✅ Так (вернёт управление сразу, результат — в колбэке):
fs.readFile('/big/file', (err, buf) => { ... });
```

В этом курсе много кода с `async/await` — это просто красивая запись «подожди, пока готово, и не блокируй остальных».

## 1.9 Словарик главы

| Термин | Значение |
|---|---|
| Клиент | Программа, которая отправляет запросы (браузер) |
| Сервер | Программа, которая отвечает на запросы |
| HTTP | Протокол «запрос → ответ» |
| Порт | Номер «двери» программы на машине (8080, 443…) |
| localhost / 127.0.0.1 | Этот же компьютер |
| LAN | Домашняя локальная сеть |
| JSON | Текстовый формат данных |
| API | Набор путей (`/api/...`) для общения с сервером |
| DOM | Дерево элементов страницы, которое рисует браузер |
| Асинхронность | Операция, которая не блокирует остальной код |
