## 13.1 Как проект зовёт ИИ

Никаких облачных SDK. Сервер запускает **локальный CLI** и читает его вывод (см. `runOpencode()` в `server.js`, конфиг `ai-opencode.json`):

```js
const { spawn } = require('child_process');

function runOpencode(promptText, cb) {
  const child = spawn('opencode', ['run', '-m', 'opencode/big-pickle', '--format', 'json'], {
    cwd: ROOT, stdio: ['pipe', 'pipe', 'pipe']
  });
  let out = '', err = '';
  child.stdout.on('data', d => { out += d; });     // накапливаем ответ
  child.stderr.on('data', d => { err += d; });
  child.on('close', code => cb(code === 0 ? null : new Error(err), out));
  child.stdin.write(promptText);                   // промпт — в stdin
  child.stdin.end();
}
```

Идея: **модель — это внешний процесс**. Плюсы: любую модель (Opencode, Ollama, llama.cpp) можно подключить, поменяв команду; не нужно тянуть огромные npm-пакеты.

### Стрим ответа клиенту

Ответ ИИ показывается «по мере печати». Сервер отдаёт его SSE-потоком:

```js
// /api/ai/chat — стрим
res.writeHead(200, { 'Content-Type': 'text/event-stream' });
child.stdout.on('data', chunk => {
  res.write('data: ' + JSON.stringify({ delta: String(chunk) }) + '\n\n');
});
child.on('close', () => { res.write('data: ' + JSON.stringify({ done: true }) + '\n\n'); res.end(); });
```

Клиент (`assistant.js`) читает поток и дописывает текст в «пузырь» чата.

**Задача 13.1.** Сделайте простейший `/api/ai/echo`: принимает `{prompt}`, зовёт `echo`-подобный процесс (или просто нейросеть через `opencode run`), стримит ответ в браузер SSE. Это ваш «hello, ИИ».

## 13.2 Контекст: что ИИ знает о вашей доске

ИИ силён, когда знает контекст. Перед отправкой промпта сервер собирает «шпаргалку» (`buildPrompt`) из данных: колонки и карточки, погода, фильмы, а для умного дома — `smart.contextSummary()` (устройства и доступные команды).

```js
function buildPrompt(userText, db) {
  const cards = (db.board?.cards || []).map(c => `- [${c.columnId}] ${c.title}`).join('\n');
  return `Ты ассистент личной канбан-доски.
Задачи:
${cards}

Запрос: ${userText}`;
}
```

Правила контекста:

- **Приватное — не подставлять** (см. фильтр банковских SMS).
- **Ограничивать объём** — не пихать в промпт 1000 карточек (модель и деньги/время).
- **Формат — простой текст**, чтобы модель легко поняла.

## 13.3 Инструменты ИИ: `assist-cli.js`

Модель умеет не только болтать, но и **действовать**. В проекте есть CLI, который ИИ вызывает как инструмент:

```bash
node assist-cli.js card add --column done --title "Купить хлеб"
node assist-cli.js cardify "...текст..."
node assist-cli.js smart on "Лампа"
```

CLI шлёт HTTP на сервер и обновляет `db` после каждого вызова (важная деталь: сервер **перечитывает** `db.json` с диска, а не держит в памяти — так два процесса не перетирают данные друг друга).

Итог: фраза в чате «добавь карточку купить хлеб» → ИИ вызывает `assist-cli.js card add` → карточка появляется на доске. Это называется **tool use / function calling**, реализованный руками через CLI.

## 13.4 Голос: распознавание и синтез

- **STT (речь → текст):** сервер запускает Python + faster-whisper (`/api/stt`). Браузер шлёт аудио, получает текст. Есть и браузерный `SpeechRecognition`.
- **TTS (текст → речь):** piper с русским голосом (`ru_RU-irina-medium`), аудио отдаётся браузеру.

Ограничение, из-за которого это стоит знать: микрофон требует **secure context** — `http://localhost` или `https://` (глава 12.7). По `http://IP` не заработает.

## 13.5 Умный дом: цикл «опрос → diff → событие → сцена»

Это красивая и простая архитектура, которую стоит понять целиком (`smart.js`, 41 проверка в тесте):

```text
   ┌──────────── опрос устройств (каждые N сек) ─────────────┐
   ▼                                                          │
 состояние ──▶ diff со прошлым ──▶ событие ──▶ сценарии ─────┘
```

- **Состояние** — только последнее (`data/smart.json`: `devices/scenes/poll/hosts/scanAt`). Историю не храним.
- **События** — кольцевой буфер в памяти (100 штук), не пишутся на диск.
- **Сцены** — правила: триггер (`change/eq/gt/lt/rise/fall` по состоянию, либо `time HH:MM`) → действие.

Защита от **петли** (сцена меняет состояние, которое её же и запускает): `busyScenes` — `Set` **в памяти** + cooldown 60 с.

> 🔥 Отличный урок: флаг «сцена выполняется» **нельзя** хранить в JSON. Если процесс упадёт в момент `busy=true`, сцена «зависнет» навсегда. Только память.

**Задача 13.3.** Реализуйте мини-умный дом: два «устройства» (файлы-заглушки), опрос раз в 2 с, при изменении — событие в SSE, одна сцена «если значение > 25 → отправить уведомление на доску». Проверьте защиту от петли.

## 13.6 Адаптеры: один контракт — много технологий

Каждое устройство говорит по-своему (HTTP, MQTT, WebSocket, Bluetooth). В проекте это скрыто за **адаптером** — функцией с тремя методами:

```js
const ADAPTERS = {
  manual:  { poll, cmd },                       // работает
  webhook: { poll, cmd },                       // работает
  http:    { poll, cmd },                       // HTTP-мост по meta.cmdUrl/pollUrl
  glagol:  { poll, cmd },                       // Яндекс Станция (облако + локальный WS)
  tuya:    { poll, cmd, stub },                 // заглушка → 501 «этап 3»
  …
};
```

Главная идея: **сценарии и события не знают**, какое устройство под капотом. Добавить новую технологию = добавить один адаптер, ничего больше не меняя.

Так же в проекте реализована Яндекс Станция: облако (`m/v3/user/devices`, действия `…/actions`), локальный WebSocket (`GlagolSocket`, RFC 6455 на `net`), токен — по OAuth device flow (вход по QR, RFC 8628). Это уже «продвинутый» уровень, но принцип тот же: адаптер + контракт.

**Задача 13.4.** Спроектируйте адаптер для любого своего устройства (например, лампы по HTTP или Telegram-бота). Опишите `poll()` и `cmd()` словами, затем реализуйте заглушку.

## 13.7 Скан локальной сети (как находят устройства)

Классическая задача администрирования, полезная сама по себе:

1. **Узнать свою сеть** — из IP и маски (`netmask`, `prefixOf`), пропустить link-local `169.254.x`.
2. **Ping-sweep** — разослать ping по диапазону (`64` параллельно, иначе долго).
3. **TCP-пробы** — по открытым портам из списка понять, что за устройство.
4. **Fingerprint + httpBrief** — прочитать заголовки/страницу, угадать тип.
5. **MAC из `ip -o neigh`** — таблица соседей даёт производителя.

Тонкость из проекта: многие устройства (Яндекс Станции, ТВ) **игнорируют** запросы с эфемерного порта — mDNS-сокет обязан биндиться на **порт 5353**.

**Задача 13.5.** Напишите скрипт, который пингует вашу подсеть и печатает живые IP. Затем добавьте проверку порта 80/443 через `net.connect`.

## 13.8 Интеграции: подключаем внешний мир

Куда развиваться дальше:

| Направление | Что сделать | Подсказка |
|---|---|---|
| Telegram-бот | уведомления/команды в чат | нужен прокси из-за RU DPI |
| Погода | Open-Meteo (без ключа) | кэш на 10–30 мин |
| RSS-лента | новости (Лента/РИА/ТАСС/Хабр) | `redirect: 'follow'`, категории по ключевым словам |
| Плеер | локальная музыка, `Range`-стрим | заголовок `Content-Range` |
| Видео | yt-dlp, стрим с сервера | нужен интернет и cookies |
| Игры | Steam API + каталоги | ключ в конфиге, не в коде |
| Карты | Яндекс.Карты API | ключ в конфиге |

Каждая — тот же рецепт: отдельный модуль (глава 10), ключи в конфиге, кэш, аккуратная обработка недоступности сети.

## 13.9 Дорожная карта обучения дальше

Вы прошли путь «от HTML до ИИ». Куда двигаться:

1. **JavaScript глубже:** асинхронность (Promise/async, событийный цикл), модули ESM, `Map/Set`, даты.
2. **Node.js глубже:** потоки (streams), `child_process`, кластеризация, `worker_threads`.
3. **Фронтенд:** компонентный подход (пусть даже мини-фреймворк своими руками), `IntersectionObserver`, Web Components.
4. **Сети:** HTTP/2, WebSocket, DNS, TLS, reverse-proxy (nginx), домены.
5. **Базы данных:** от JSON-файлов к SQLite (`better-sqlite3`), затем к Postgres + миграции.
6. **Инфраструктура:** Docker, CI/CD (GitHub Actions), мониторинг.
7. **Прикладной ИИ:** embeddings и поиск, RAG, локальные модели (Ollama), tool use.

Практическое правило роста: **каждая новая тема — сразу в проект.** Прочитали про streams — перепишите раздачу музыки на поток. Прочитали про SQLite — переведите `db.json`. Так знания закрепляются.
