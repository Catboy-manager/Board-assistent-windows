## 2.1 Установка Node.js

### Linux (Ubuntu/Debian/Mint)

```bash
# проверяем, нет ли уже
node -v

# если нет — из репозитория (достаточно для курса)
sudo apt update && sudo apt install -y nodejs npm
node -v   # должно быть >= 18
```

Если в репозитории старая версия (< 18) — поставьте свежую с https://nodejs.org (LTS-сборка) или через `nvm`:

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash
source ~/.bashrc
nvm install --lts
node -v
```

### Windows

1. Скачайте LTS-установщик с https://nodejs.org и запустите (галочки по умолчанию).
2. Откройте **Windows Terminal** и проверьте: `node -v`, `npm -v`.

### macOS

```bash
brew install node     # если есть Homebrew
# или установщик с nodejs.org
node -v
```

**Итог:** команда `node -v` выводит версию, `npm -v` — версию пакетного менеджера.

> 📌 В курсе проверено: **Node v22.22.1**. Подойдёт любая 18+ (в 18 появился встроенный `fetch`, он нам понадобится в главах 9–11).

**Задача 2.1.** Установите/проверьте Node, запишите версию. Напишите в терминале `node -e "console.log(process.version, process.platform)"`.

## 2.2 Терминал: минимальный набор

Терминал пугает новичков, но полезных команд десять. Откройте его и по очереди выполните:

```bash
pwd                      # где я нахожусь (текущая папка)
ls -la                   # что в папке (все файлы, включая скрытые)
mkdir -p ~/my-kanban     # создать папку для практики
cd ~/my-kanban           # перейти в неё
echo "привет" > hi.txt   # записать текст в файл
cat hi.txt               # показать файл
node --version           # версия Node
clear                    # очистить экран (или Ctrl+L)
```

Навигация: `cd ..` — на уровень выше, `cd /` — в корень диска, `Tab` — автодополнение имён, `↑` — предыдущая команда в истории.

**Windows-отличия:** вместо `ls` — `dir`, вместо `mkdir`/`cat` — те же имена (работают), путь типа `C:\Users\you\my-kanban`, `cd` без кавычек.

## 2.3 Первая программа

Самый быстрый способ — «из командной строки»:

```bash
node -e "console.log('Привет, мир!'); console.log(2 + 2)"
```

Более правильный — файл. Создайте `~/my-kanban/hello.js` (через редактор, не через терминал) со следующим содержимым:

```js
'use strict';

const who = 'будущий разработчик';
console.log('Привет, ' + who + '!');
console.log(`Сегодня ${new Date().toLocaleDateString('ru-RU')}`);
console.log('Сумма:', 21 * 2);
```

Запуск:

```bash
node hello.js
```

Разбор:

- `'use strict;'` — строгий режим: JavaScript начнёт ругаться на ваши ошибки (опечатки, работа с необъявленными переменными) сразу, а не молча делать странное. Во всех файлах проекта он стоит.
- `console.log(...)` — печать в терминал. Это ваш главный инструмент отладки.
- `` `...${...}` `` — шаблонные строки: удобная вставка значений.

**Задача 2.3 (самостоятельная).** Напишите `calc.js`, который печатает таблицу умножения на 7 (от 1 до 10) в виде `7 x 3 = 21`. Используйте цикл `for`.

## 2.4 Ошибки: как их читать

Ошибка — не приговор, а **инструкция**. Пример: допустим в `hello.js` опечатка (забыли скобку).

```bash
$ node hello.js
/tmp/hello.js:5
console.log('Сумма:', 21 * 2)
                        ^

SyntaxError: Unexpected token ')'
    at wrapSafe (node:internal/modules/cjs/loader:...)
```

Читаем сверху вниз:

1. **Имя файла и строка** (`hello.js:5`) — где смотреть.
2. **Строка с кодом + стрелка** — где именно сломалось.
3. **Тип ошибки**: `SyntaxError` — не понял код (опечатка), `TypeError` — получил не тот тип (`cannot read properties of undefined`), `ReferenceError` — нет такой переменной, `ReferenceError/Cannot find module` — не так подключили модуль.

**Три правила борьбы с ошибками:**

1. Не гуглите «почему не работает» — сначала **перечитайте текст ошибки целиком** (там почти всегда есть файл и строка).
2. `node --check файл.js` — проверка синтаксиса **без запуска**. Быстро ловит опечатки. Так проект проверяет и в AGENTS.md.
3. Если сервер «упал» — посмотрите, **что он напечатал в терминале**: серверная ошибка всегда видна там, а в браузере — лишь «500».

## 2.6 npm: пакеты и package.json

**npm** — менеджер пакетов: каталог из миллионов готовых библиотек + команды для их установки.

```bash
npm init -y        # создать package.json (паспорт проекта)
npm install express  # поставить библиотеку (появится node_modules/)
npm ls             # что установлено
```

`package.json`:

```json
{
  "name": "my-kanban",
  "version": "1.0.0",
  "scripts": { "start": "node server.js" },
  "dependencies": {}
}
```

Ключевая мысль курса и проекта NeuroBoard: **внешних зависимостей может не быть вообще**. Весь сервер написан на модулях из коробки Node: `http`, `fs`, `path`, `os`, `child_process`. Почему это круто:

- ничего не отпадает при обновлении чужих библиотек;
- `git clone` + `node server.js` = работает, без `npm install`;
- вы видите **весь код**, который исполняется (а чужой код нужно уметь читать — это отдельный навык).

Зато в проекте есть **внешние программы**, которые Node вызывает как команды: `yt-dlp` (видео), `piper` (озвучка), `faster-whisper` (распознавание речи). Это штатное «соседство»: библиотеки могут быть не только JS.

**Задача 2.6.** Создайте в `~/my-kanban` файл `package.json` (`npm init -y`), добавьте в него `"scripts": {"start": "node hello.js"}` и запустите `npm start`. Убедитесь — сработало.

### Уровень 3 — DevTools в браузере (F12)

## 2.8 Git: версии вашего кода

Git — «тайм-машина» для проекта. Без него любая случайная правка безвозвратна.

```bash
cd ~/my-kanban
git init                  # завести репозиторий
git status                # что изменилось
git add .                 # положить изменения в «корзину»
git commit -m "первая версия"   # сохранить снимок
git log --oneline         # история снимков
git diff                  # что именно изменилось с прошлого раза
```

И обязательно `.gitignore` (файл со списком «в git не надо»):

```gitignore
node_modules/
data/
uploads/
config.json
*.log
```

В NeuroBoard так и сделано: секреты (`config.json`), данные (`data/`), ключи (`ssl/`) в git не попадают.

## 2.9 Как запускается настоящий проект

```bash
cd ~/kanban-board
node --check server.js    # 1. синтаксис в порядке?
node server.js            # 2. запуск вручную (Ctrl+C — остановить)
```

В терминале появится:

```text
  ==== Kanban Board ====
  Local:   http://localhost:8080
  LAN:     http://192.168.1.100:8080  (wlan0)
```

Это код `startLogs()` из `server.js:1226`. В продакшене проект работает как **systemd-сервис** (запускается сам при загрузке ПК):

```bash
systemctl status kanban-board
sudo systemctl restart kanban-board
journalctl -u kanban-board -n 50   # лог, если что-то не так
```

Подробнее — глава 12.

Потом остановите его на время (`sudo systemctl stop kanban-board`), запустите **свой** `node server.js` в ручном режиме на другом порту: `PORT=8099 node server.js` — и проверьте `curl http://localhost:8099/api/ping`.
